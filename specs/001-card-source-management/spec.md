# Feature Specification: 後台卡片與來源管理總覽頁

**Feature Branch**: `feature/admin`

**Created**: 2026-07-27

**Status**: Draft

**Input**: User description: "我想要多一個頁面給管理者使用，目的是要能夠一目了然看加了哪些卡片、來源，因為我想要能夠開關卡片的追蹤，與來源的使用，然後還要能夠篩選卡片、來源的相關資訊，確切的開關。UI 的部份，我想要用 Accordion 的方式處理，還有就是列表我想要用無限滾動的形式處理，然後點擊卡片之後，才會去 load 來源好了，所以會是點擊 Accordion 才發生 fetch 來源這樣，那頁面如截圖。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 一目了然檢視所有卡片與其來源（Priority: P1）

管理者進入一個獨立的後台管理總覽頁，就能看到目前系統追蹤的所有卡片清單（以 Accordion 形式呈現，含已停用者）。每張卡片以摘要列顯示關鍵資訊（卡名、卡號、系列、語言、狀態、追蹤開關狀態、來源數量、最新價與最後更新時間），不需逐一點進詳情。清單以無限滾動分批載入，捲動到底會自動接續載入下一批。只有在管理者點開某張卡片的 Accordion 時，才會去載入該卡片底下的來源明細（延遲載入）。

**Why this priority**: 這是使用者需求的第一支柱——「一目了然看加了哪些卡片、來源」。沒有這個檢視，後續的開關與篩選都無從操作。單獨完成即可交付「集中檢視」的價值。

**Independent Test**: 以管理者身分登入後開啟此頁，確認能看到第一批卡片摘要；持續向下捲動能載入更多；點開任一卡片能看到其來源明細，且來源是在點開當下才載入（未展開的卡片不預先載入來源）。

**Acceptance Scenarios**:

1. **Given** 系統已有多張卡片，**When** 管理者開啟總覽頁，**Then** 頁面以 Accordion 列出第一批卡片，每列顯示卡名、卡號、系列、語言、狀態、追蹤開關狀態、來源數量、最新價與最後更新時間。
2. **Given** 卡片數量超過單批數量，**When** 管理者捲動到清單底部，**Then** 系統自動載入並接續顯示下一批卡片，無需手動換頁。
3. **Given** 一張尚未展開的卡片，**When** 管理者點開該卡片的 Accordion，**Then** 系統於此時才發出請求載入該卡片的來源明細並顯示（含每個來源的類型、名稱、幣別、使用開關狀態、最後成功時間、最後錯誤）。
4. **Given** 一張已展開且來源已載入的卡片，**When** 管理者收合再重新展開，**Then** 系統不重複發出載入請求（沿用已載入的結果，除非管理者主動重新整理）。
5. **Given** 一張沒有任何來源的卡片，**When** 管理者展開該卡片，**Then** 顯示「尚無來源」的空狀態，而非錯誤。

---

### User Story 2 - 精準開關卡片追蹤與來源使用（Priority: P1）

管理者可在同一頁面上，直接切換單一卡片的「追蹤」開關，以及單一來源的「使用」開關；切換後立即生效並持久保存。頁面需清楚呈現兩層開關的關係：當一張卡片的追蹤被關閉時，其底下的所有來源即使個別為「使用中」，在下次抓價時也不會被抓取。

**Why this priority**: 這是使用者需求的第二支柱、也是這頁存在的核心目的——「開關卡片的追蹤，與來源的使用……確切的開關」。與 US1 併行即構成可用的管理主流程。

**Independent Test**: 切換某張卡片的追蹤開關，重新整理頁面後狀態仍為新值；切換某個來源的使用開關亦然；當卡片追蹤關閉時，頁面明確標示其來源「不會被抓取」。

**Acceptance Scenarios**:

1. **Given** 一張追蹤中的卡片，**When** 管理者關閉其追蹤開關，**Then** 該卡片狀態即時更新為停用，且重新整理頁面後仍為停用。
2. **Given** 一張停用中的卡片，**When** 管理者開啟其追蹤開關，**Then** 該卡片恢復為追蹤中並持久保存。
3. **Given** 一張已展開的卡片下有多個來源，**When** 管理者關閉其中一個來源的使用開關，**Then** 僅該來源變為停用，其他來源與卡片狀態不受影響，且變更持久保存。
4. **Given** 一張追蹤被關閉的卡片，**When** 管理者檢視其展開後的來源，**Then** 頁面明確標示「此卡片追蹤已關閉，來源不會被抓取」，即使個別來源仍顯示為使用中。
5. **Given** 開關切換的儲存動作失敗，**When** 系統收到失敗回應，**Then** 頁面還原為切換前的狀態並提示失敗，不讓畫面顯示與實際不符的狀態。

---

### User Story 3 - 篩選卡片與來源資訊（Priority: P2）

管理者可依條件篩選要檢視的卡片（例如關鍵字、語言、狀態別、追蹤狀態），縮小清單以便針對特定範圍操作開關。在展開的卡片內，也可依來源類型與使用狀態篩選其來源。

**Why this priority**: 當卡片與來源數量成長時，篩選讓管理者能聚焦目標對象；屬於提升效率的增強，但不阻擋 US1／US2 的核心價值。

**Independent Test**: 套用一組卡片篩選條件後，清單只顯示符合條件者並從第一批重新載入；在展開的卡片內套用來源篩選後，只顯示符合條件的來源。

**Acceptance Scenarios**:

1. **Given** 清單顯示全部卡片，**When** 管理者輸入卡名／卡號關鍵字，**Then** 清單重置並只顯示符合關鍵字的卡片（仍支援無限滾動）。
2. **Given** 清單顯示全部卡片，**When** 管理者將追蹤狀態篩選為「僅停用」，**Then** 清單只顯示追蹤已關閉的卡片。
3. **Given** 管理者同時套用多個卡片篩選條件（如語言＋追蹤狀態），**When** 條件生效，**Then** 清單只顯示同時符合所有條件的卡片。
4. **Given** 一張已展開、含 api 與 crawler 混合來源的卡片，**When** 管理者將來源類型篩選為「crawler」，**Then** 該卡片內只顯示 crawler 來源。
5. **Given** 一組篩選條件下沒有任何符合的卡片，**When** 條件生效，**Then** 顯示「查無符合條件的卡片」空狀態。

---

### Edge Cases

- 捲動到清單底部但已無更多卡片時，顯示「已到底」提示，且不再重複發出載入請求。
- 展開卡片載入來源時發生錯誤（例如網路失敗），於該卡片區塊內顯示錯誤與「重試」，不影響其他卡片與整頁。
- 快速連續切換同一個開關時，以最後一次操作為準，避免畫面與後端狀態互相打架。
- 篩選條件變更時，若仍有上一批載入中的請求，需捨棄過期結果、只採用最新條件的結果。
- 卡片摘要中「最新價／最後更新時間」尚無資料（從未抓過價）時，顯示「—」而非空白或錯誤。
- 管理者 token 過期或未登入時進入此頁，導向登入頁，不顯示殘缺畫面。
- 關閉的來源為該卡「最後一個啟用中來源」時，先跳確認 modal；管理者取消則來源與卡片狀態皆不變更。
- 卡片本已為不追蹤時，關閉其最後一個啟用來源仍會停用該來源，卡片維持不追蹤（不因此產生額外變更或錯誤）。

## Clarifications

### Session 2026-07-27

- Q: 關閉「來源使用開關」時，確認 modal 應在什麼情況出現、顯示什麼？並如何處理卡片？ → A: 僅當關閉的是該卡「最後一個啟用中來源」時才跳確認 modal（警告：關閉後這張卡片將沒有任何啟用中來源、價格不再更新）；管理者確認後，於同一動作內同時停用該來源並將所屬卡片設為不追蹤（`isActive=false`），兩者一併持久化。關閉「非最後來源」則不跳 modal、直接停用、且不改變卡片狀態。判斷依據為該卡片當前已呈現的來源清單（一個來源只屬一張卡，不需也不新增「依來源反查卡片」查詢）。
- Q: 卡片因「最後來源被關閉」自動變成不追蹤後，之後重新啟用或新增來源是否自動回復追蹤？ → A: 不自動回復；連動僅「關閉最後啟用來源 → 卡片自動不追蹤」單一方向，卡片追蹤僅由管理者手動重新開啟。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 提供一個獨立於現有後台頁的「卡片與來源管理總覽頁」，且 MUST 僅限已登入的管理者存取。
- **FR-002**: 總覽頁 MUST 以 Accordion 形式列出卡片（含已停用者），每張卡片的摘要列 MUST 顯示：卡名、卡號、系列、語言、狀態別（condition/grade）、追蹤開關狀態、來源數量、最新價與最後更新時間。
- **FR-003**: 卡片清單 MUST 以無限滾動分批載入；當管理者捲動接近清單底部時，系統 MUST 自動載入並接續顯示下一批，直到沒有更多資料。
- **FR-004**: 每張卡片的來源明細 MUST 採延遲載入——僅在管理者展開該卡片的 Accordion 時才發出載入請求；同一張卡片已載入過的來源在重複展開時 SHOULD NOT 重複請求（除非管理者主動重新整理）。
- **FR-005**: 展開後的來源明細 MUST 顯示每個來源的：類型（api／crawler）、來源名稱、幣別、使用開關狀態、最後成功時間、最後錯誤訊息（若有）。
- **FR-006**: 管理者 MUST 能於此頁切換單一卡片的「追蹤」開關，切換 MUST 立即持久化並反映於畫面。
- **FR-007**: 管理者 MUST 能於此頁切換單一來源的「使用」開關，切換 MUST 立即持久化並反映於畫面（關閉單一來源的確認與連動特例見 FR-015～FR-018）。
- **FR-008**: 頁面 MUST 清楚呈現兩層開關的關係：當卡片追蹤為關閉時，其底下所有來源（即使個別為使用中）於抓價時皆不會被抓取；此狀態 MUST 於 UI 明確標示，避免管理者誤以為個別來源仍會運作。
- **FR-009**: 系統 MUST 提供卡片層級篩選，至少包含：關鍵字（比對卡名／卡號）、語言、狀態別（condition/grade）、追蹤狀態（全部／僅追蹤中／僅停用）。
- **FR-010**: 系統 MUST 提供來源層級篩選（作用於已展開卡片內的來源清單），至少包含：來源類型（api／crawler）與使用狀態（全部／僅使用中／僅停用）。
- **FR-011**: 任一卡片層級篩選條件變更時，清單 MUST 重置並自第一批重新載入，只顯示符合條件的卡片。
- **FR-012**: 任一開關切換若持久化失敗，系統 MUST 將該開關還原為切換前狀態並提示管理者失敗，MUST NOT 讓畫面停留在與實際不符的狀態。
- **FR-013**: 頁面 MUST 對「載入中」「載入更多中」「已到底」「查無資料」「來源載入失敗可重試」等狀態提供清楚的視覺回饋。
- **FR-014**: 本頁 MUST NOT 改變既有抓價 job 的挑選邏輯與其他後台頁的行為；本功能為在既有兩層 `isActive` 語意之上新增的檢視／操作介面。
- **FR-015**: 當管理者關閉某來源的「使用」開關，且該來源為其所屬卡片「最後一個啟用中來源」時，系統 MUST 先以確認 modal 提示，明確警告「關閉後這張卡片將沒有任何啟用中來源，價格不再更新」；管理者取消時 MUST 不做任何變更（來源與卡片狀態皆不變）。
- **FR-016**: 管理者於 FR-015 的 modal 確認後，系統 MUST 於同一次動作內同時將該來源停用並將其所屬卡片設為不追蹤（`isActive=false`），兩者 MUST 一併持久化；若持久化失敗，MUST 將來源與卡片一併還原為動作前狀態並提示失敗（沿用 FR-012）。
- **FR-017**: 關閉「非最後一個啟用中來源」的來源時，系統 MUST NOT 跳確認 modal，MUST 直接停用該來源，且 MUST NOT 改變其所屬卡片的追蹤狀態；SHOULD 對此提供「已關閉／可復原」的輕量提示。
- **FR-018**: 因 FR-016 而自動被設為不追蹤的卡片，MUST NOT 因其後任一來源被重新啟用或新增而自動回復追蹤；卡片追蹤 MUST 僅由管理者手動重新開啟（來源→卡片連動僅「關閉最後啟用來源 → 卡片不追蹤」單一方向）。

### Key Entities *(include if feature involves data)*

- **卡片（Card）**: 被追蹤的一張寶可夢卡牌。管理相關屬性：名稱、卡號、系列、語言、狀態別（condition/grade）、追蹤開關（是否啟用追蹤）、最新價與幣別、最後抓取時間、所屬來源數量。一張卡片可有多個來源。
- **價格來源（PriceSource）**: 一張卡片的其中一個外部查價來源。管理相關屬性：類型（api／crawler）、來源名稱、幣別、使用開關（是否啟用使用）、最後成功時間、最後錯誤訊息。隸屬於單一卡片。
- **兩層追蹤語意**: 一個來源是否會在抓價時被實際抓取，取決於「該來源為使用中」且「其所屬卡片為追蹤中」兩者同時成立；任一為關閉，該來源即被排除。此為既有系統語意，本頁忠實呈現並提供操作介面，不改變其定義。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理者能在單一頁面內看到系統所有卡片及其追蹤狀態與來源數量，並可在同頁完成追蹤／使用開關的切換，全程無需離開此頁。
- **SC-002**: 開啟總覽頁後，第一批卡片摘要於 2 秒內出現。
- **SC-003**: 點開任一卡片後，其來源明細於 2 秒內出現。
- **SC-004**: 切換任一開關後，畫面於 1 秒內反映新狀態，且重新整理頁面後狀態仍為新值（成功持久化）。
- **SC-005**: 套用任一組篩選條件後，清單只呈現符合條件的卡片／來源，無不符者混入。
- **SC-006**: 當卡片數達到 200 張時，頁面仍以分批方式載入而非一次載入全部，首屏卡片數不超過單批上限。
- **SC-007**: 至少 90% 的管理者能在不需額外說明的情況下，正確理解「卡片追蹤關閉時其來源不會被抓取」的兩層開關關係。
- **SC-008**: 關閉某卡「最後一個啟用中來源」時，系統於同一動作內完成「停用該來源＋將卡片設為不追蹤」，重新整理頁面後兩者狀態一致；關閉「非最後來源」時卡片追蹤狀態不受影響。

## Assumptions

- **與現有後台頁並存**：本頁是「多一個」獨立的管理頁，與現有「後台管理」頁（新增卡牌／來源、手動更新、job 狀態）並存，並可自導覽列進入；新增卡牌／來源等資料建立動作仍留在現有後台頁，本頁聚焦於「檢視 ＋ 兩層開關 ＋ 篩選」。
- **開關對應既有 `isActive`**：「卡片追蹤開關」對應卡片的啟用狀態、「來源使用開關」對應來源的啟用狀態；兩者皆沿用既有資料語意，關閉即等同軟停用（不刪除資料）。
- **抓價語意不變**：抓價時「來源被抓取」的條件維持既有規則——來源啟用且所屬卡片啟用兩者同時成立；本功能不修改此挑選邏輯。
- **來源篩選作用範圍**：來源層級篩選作用於「已展開卡片內」的來源清單，與延遲載入的架構一致；不做「跨全部卡片依來源條件過濾卡片」的查詢。
- **無限滾動單批數量**：以每批固定張數（預設 20 張）分批載入；確切數字於實作階段調校，不影響本規格。
- **卡片預設排序**：清單依「最後更新時間」由新到舊排序，作為預設檢視順序。
- **開關即時生效**：開關採即時切換並立即保存（無需額外「儲存」按鈕）。
- **權限模型沿用現況**：沿用既有單一管理者角色與 JWT 登入機制，不新增角色或細分權限。
- **依賴既有後台 API 能力**：本頁依賴既有的後台卡片列表、依卡片查來源、以及卡片／來源啟用狀態更新能力；為支援無限滾動，卡片列表查詢需具備分批（分頁）能力。
- **一來源只屬一卡、無共用來源**：`PriceSource` 隸屬單一卡片，關閉某來源的影響範圍恆為其所屬那一張卡；因此不需要、也不新增「依來源反查卡片」的 API，「是否為最後一個啟用來源」由該卡已呈現的來源清單即可判定。
- **來源→卡片連動為單向**：僅「關閉卡片最後一個啟用來源 → 該卡片自動變不追蹤」這一方向成立；反向（重新啟用或新增來源）不會自動讓卡片回到追蹤中，需管理者手動開啟。此連動為本頁操作層的行為，不改變抓價 job「來源啟用且卡片啟用才抓取」的挑選定義（FR-014）。
