# Quickstart — 驗證指南

**Feature**: 卡牌詳情頁多來源台幣價格趨勢圖
**Date**: 2026-08-10

用來證明本功能端到端可用。所有指令**從 repo 根目錄執行**（專案守則）。

---

## 前置需求

- Node.js v24+
- 本機 PostgreSQL 已啟動：`docker compose up -d db`
- 根目錄 `.env` 已設定 `DATABASE_URL`
- 對外網路（驗證外部市場行情用；無網路時見下方「離線」段落）

---

## 建立驗證資料

```bash
npm run db:reset && npm run db:seed && npm run db:seed:admin && npm run job:once
```

**預期輸出**：

- seed 過程若 `Currency` 表為空，會印出使用備援匯率的警告（FR-027）
- 建立三張具備 90 天歷史的卡牌，其中皮卡丘 V 具備多個來源（FR-026、FR-028）
- `job:once` 完成後不出現未處理的例外

**檢查資料是否正確**：

```bash
npm run db:studio
```

在 `PriceSnapshot` 確認：`priceTwd` 不應大量為 `null`；
皮卡丘 V 應有兩個以上 `provider` 各自涵蓋約 90 天。

## 瀏覽器自動化驗證（MCP）

下列標示 🤖 的項目**應以 chrome-devtools MCP 或 playwright MCP 驗證**，不要靠目視 —
它們不是眼睛看得準的東西（網路請求次數、SVG 屬性、節點計數）。

驗證目標頁面：`http://localhost:5173`，進入**皮卡丘 V** 的詳情頁。

常用檢查手法：

| 要驗什麼 | 手法 |
|---|---|
| 外部請求次數 | 讀取網路請求清單，過濾外部網域後計數 |
| 線的顏色與線型 | 讀 `path.recharts-line-curve` 的 `stroke` 與 `stroke-dasharray`，斷言互異 |
| 圖例線型 | 讀圖例 SVG 節點的 `stroke-dasharray` |
| 資料點數量 | 計算 `.recharts-dot` 節點數 |
| 空狀態文字 | 取頁面文字後做字串斷言 |
| 視窗尺寸行為 | 設定 viewport 寬度後重新讀取 DOM |
| 主控台無錯誤 | 讀取 console 訊息並過濾 error 等級 |

完整對應表見 [plan.md 的「驗證策略」](./plan.md)。

## 驗證情境

開啟前台，進入**皮卡丘 V** 的詳情頁。

### 情境 1 — 基本趨勢（US1 / P1）

- [ ] 頁面只有**一張**價格趨勢圖（原本的兩張已合併）
- [ ] 橫軸為日期、一天一格；縱軸為台幣並有千分位
- [ ] 線是連續的，不是零星幾個點

### 情境 2 — 多來源比較（US2 / P2）

- [ ] 每個來源各自一條線，線數等於該卡有台幣資料的來源數
- [ ] 圖例列出每條線的來源名稱
- [ ] 🤖 **每條線的顏色與線型都不同** — 讀 `stroke` 與 `stroke-dasharray`，斷言兩組值皆互異（FR-029）
- [ ] 🤖 **圖例 icon 呈現對應線型** — 讀圖例節點的 `stroke-dasharray`，與線條比對（FR-030）
- [ ] 停留在某一天時，列出該日各來源的台幣價；當日無資料的來源不出現

### 情境 3 — 區間切換（US3 / P3）

- [ ] 三顆鈕：7 天／1 個月／3 個月
- [ ] 切換不重新載入頁面，且三個區間的日期範圍確實不同
- [ ] 🤖 3 個月區間**不顯示資料點** — 計算 `.recharts-dot` 節點數應為 0（FR-013）
- [ ] 🤖 **反覆切換區間，對外部服務的請求最多 2 次** — 讀網路請求清單過濾外部網域後計數（SC-012、FR-032）

### 情境 4 — 外部市場行情（US4 / P4）

- [ ] 出現「TCGPlayer 市場價」線，且與我方 `tcgplayer` 來源是**分開的兩條**
- [ ] 該線的值是台幣，與其他線在同一個縱軸尺度上
- [ ] 停留在有成交量的日期時，看得到成交量
- [ ] 3 個月區間下該線的資料點較稀疏（每 3 天），中間**沒有被補值**

### 情境 5 — 無障礙

- [ ] 疑似異常的資料點以**不同形狀**呈現，停留時說明它是疑似異常
- [ ] **（目視）** 將瀏覽器切換為灰階或開啟色覺模擬，仍能區分每一條線

> 灰階辨識度保留為人工判斷 — 屬性互異不等於視覺上分辨得出來，這需要人眼實際確認。

### 情境 6 — 窄螢幕

- [ ] 🤖 viewport 設為 767px 後重新載入 → 區間鈕只剩兩顆，且不含「3 個月」（FR-024）
- [ ] **（目視）** 在寬螢幕點選 3 個月，然後**用滑鼠拖曳瀏覽器視窗**縮到 767px 以下 →
      當前選取自動變為「1 個月」，畫面不空白不報錯（FR-025）

> **為何 FR-025 無法自動化**：自動化工具是用 CDP 覆寫 viewport 尺寸，
> 這不會發出真實的 `matchMedia` `change` 事件；而合成事件只能送達**同一個**
> `MediaQueryList` 物件上的監聽器（`window.matchMedia()` 每次呼叫都回傳新物件），
> 跨不到元件內部那個實例。只能靠真實的視窗拖曳觸發。

### 情境 7 — 邊界與降級

- [ ] **リザードン V**（單一來源）→ 只畫一條線，不報錯
- [ ] **ミュウツー GX**（僅單日一筆）→ 正常渲染，不崩潰
- [ ] 下方「歷史價格」表格與「匯出 CSV」行為與改動前相同（SC-008）
- [ ] 🤖 圖上任一資料點的台幣數字，都能在下方表格找到同日同來源的對應紀錄 — 同時讀圖表資料節點與表格列後程式比對（SC-004）
- [ ] 🤖 上述每一頁的瀏覽器主控台皆無 error 等級訊息（FR-016、FR-020）

### 情境 8 — 換算失敗（FR-019、SC-013）

清空匯率表後重跑抓價：

```bash
npm run db:studio   # 手動清空 Currency 表
npm run job:once
```

- [ ] 圖表顯示**使用者導向**的訊息，讓訪客理解價格暫時無法以台幣呈現
- [ ] 🤖 訊息中**不出現任何指令、檔案路徑或系統內部細節** — 取頁面文字後斷言不含 `npm`、`run `、`.js`、`prisma` 等字串（FR-019、SC-013）
- [ ] 診斷資訊只出現在後端紀錄或瀏覽器主控台，不在畫面上

還原：

```bash
npm run currency:once && npm run job:once
```

## 離線 / 外部服務不可用時

外部市場行情取得失敗屬可接受狀態（FR-016）。此時：

- 情境 1、2、3、5、6、7、8 仍應全數通過
- 情境 4 略過，但圖表**必須照常呈現其餘來源**，不得出現錯誤畫面

這也是 PRD 第二十三章「Demo 當天來源失敗」的備援路徑。
